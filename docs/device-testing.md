# Android / iPhone 真机验收

两端均需记录手机型号、系统版本、微信版本、基础库版本、代码包版本。请使用真实 AppID 预览，先验证几十 KiB 文件，再测试较大的文件。测试结果需要在手机上实际记录，不能用桌面 WASM 测试代替。

## 基础接收

1. Android 和 iPhone 分别启动小程序，点击开始接收，检查隐私与相机授权弹窗。
2. 拒绝权限，确认界面有明确错误和“打开权限设置”；重新授权后可重试。
3. 从 cimbar.org 发送一个已知 SHA-256 的文件，双方设为 B。码图四角完整入镜，接收完成后核对文件大小。
4. 输入中文文件名并保留扩展名，确认保存；退出小程序，再打开“已接收文件”，确认记录与内容仍存在。
5. 使用“导出 / 转发”转到自己的文件传输助手，下载导出的文件到电脑，核对 SHA-256。
6. Mini / Micro / 旧版 4 色 / 旧版 8 色使用匹配发送端分别测试；模式不一致时不应显示虚假成功。

## 暂停、退出与重试

- 接收中点击暂停，再继续；进度保留。切后台、锁屏、打开文件列表后返回也需检查。
- 接收中点击重新开始，确认后进度清空；发送第二个文件应能完成。
- 刚解码完成但尚未命名时退出，在文件列表找到“待命名”记录并完成命名。
- 在写入过程中终止进程，确认半文件不会显示为接收成功。此时尚未完整落盘的数据需重新接收。
- 拒绝相册权限、取消转发、目标文件不支持预览时，确认本地文件仍保留。
- 重复接收相同文件，命名冲突时生成“文件 (2).扩展名”，不覆盖先前内容。
- 确认删除只删除所选记录。该操作不可恢复。

## 画质与性能

记录 100 KiB、1 MiB、5 MiB 文件的接收时间、丢帧表现、发热和后台恢复结果。分别测试轻微倾斜、距离变化、屏幕反光。当前最高解码频率 4 帧/秒，同时仅一帧在解码；实际速度由设备决定。相机回调分辨率由微信决定，不一定与预览分辨率相同。iPhone 优先 Worker 直接取帧，Android 和兼容路径按单帧启动／停止监听，而非持续接收后仅在 JS 回调丢帧。

首版不含镜头畸变标定或自动模式识别。较强透视、广角镜头畸变、低像素帧及频繁对焦可能降低成功率；先调整距离和发送模式，再记录具体机型问题。

## 正方形画面与实时速度（square-speed-3）

1. 检查取景区域为正方形，完整码图四个角标均在框内。读取下方真实尺寸：720×1280 的原始帧应对应 720×720 解码，1080×1920 对应 1080×1080。更改预览宽高不代表原始分辨率提高。
2. 转动手机或切后台恢复后检查显示尺寸及取景范围；确认四角没有被中央裁剪区域截掉。若预览与实际视野不一致，记录机型和两个尺寸供排查。
3. 收到有效帧后速度应以 KiB/s 等单位显示。遮住码图或持续显示同一帧，约 3 秒后应回落到零；不能把重复帧算成新的文件数据。
4. 暂停时显示“已暂停”；继续后重新计算短时速度，不应把暂停时长算进分母，也不应产生积压数据的假峰值。
5. 完成、退出或收到内存警告后，速度刷新计时器应停止，不产生后台持续刷新。
6. 接收页和文件列表底部的源码／Star 入口应复制公开仓库链接，并提示在浏览器打开；取消或复制失败不应声称已经 Star。

## iPhone 1 MB 内存退出回归（含 memory-2 修复）

已知旧版表现：十几 KiB 文件可成功；约 1 MB 文件在接收进度约 15% 时退出，提示内存占用过多。不是解码完成后的保存阶段。以下步骤用于复测，不能以本地测试通过代替。

1. 开发者工具重新编译并生成新的预览二维码，手机打开新版。无需重建 WASM，也无需清理小程序数据（清理会丢失已保存文件）。
2. 用原来的同一个 1 MB 文件、相同模式测试；建议发送速度先设为 4～6 帧/秒。完整接收、重命名保存，再导出核对 SHA-256。
3. 点击页面底部“复制接收诊断”，确认 `revision` 为 `square-speed-3`。记录 `transport`：支持的 iPhone 应为 `ios-worker-camera`；`sampled-copy` 表示兼容采样路径，并非接收失败。`width/height` 是相机尺寸，`decodeWidth/decodeHeight` 是裁剪后的实际解码尺寸。
4. 在约 15% 处手动暂停／恢复一次，确认进度不清空。接收过程中切后台再返回也需测试；重复接收同一文件至少三次。
5. 若收到系统内存警告，首次应自动暂停并保留进度。稍候继续；若再次警告则终止会话并提示重新接收，已保存文件不受影响。加载阶段或 Android 严重警告直接释放线程。
6. 若再次退出，重新打开后**先复制接收诊断再开始新接收**，将诊断和当时的现象提供给开发者。快照每 5 秒保存一次，可能略早于退出瞬间；若系统未发警告，`memoryWarnings` 也可能为 0。

诊断中的 `heapBytes` / `peakHeapBytes` 仅为 WASM 线性内存，不是微信进程总内存。桌面 `npm run test:memory` 的两组 1 MiB 长时间测试保持 32 MiB，仅能排查核心持续增长；真实相机和微信跨线程缓冲必须在手机上观察。诊断仅保留一份本机快照，不记录像素、文件内容或文件名，不自动上传。
